解决办法：通过服务商控制台或已有 SSH 会话，在目标 VPS 上以 root 执行以下检查。

1. 查看生效值，期望两项均为 yes；主配置写了 yes 不代表实际生效。
```sh
sshd -t && sshd -T | grep -E '^(permitrootlogin|passwordauthentication) '
```

2. 若仍为 no 或 prohibit-password，检查 Include、Match 和配置片段。50-cloud-init.conf 可能先设置 PasswordAuthentication no，后面的 yes 无法覆盖先读到的值。
```sh
grep -RniE '^[[:space:]]*(Include|Match|PermitRootLogin|PasswordAuthentication|AuthenticationMethods|AllowUsers|DenyUsers)' /etc/ssh/sshd_config /etc/ssh/sshd_config.d/
```

3. 仅当已确认 sshd_config 提前 Include 了 /etc/ssh/sshd_config.d/*.conf，且后面的 cloud-init 片段禁用密码认证时，可添加更早加载的配置。此操作开启 root 密码远程登录，仅在你需要此方式时执行，并保留当前控制台会话；同名文件已存在则先查看，不覆盖。
```sh
(set -C; printf '%s\n' 'PermitRootLogin yes' 'PasswordAuthentication yes' > /etc/ssh/sshd_config.d/00-miao-password-auth.conf)
```

无上述 Include 时修改实际生效的配置；有 Match 时须按 root 和 Miao 实际来源地址核对，不能只看无连接条件的 sshd -T。

4. 校验、重新加载并复核；语法检查失败先修正，不要重启服务。两项均为 yes 后回 Miao 重试。
```sh
sshd -t && {
  if [ -d /run/systemd/system ]; then
    systemctl reload sshd || systemctl reload ssh
  else
    rc-service sshd reload
  fi
}
sshd -T | grep -E '^(permitrootlogin|passwordauthentication) '
```

5. 仍失败时确认输入的是 root 密码，检查 AuthenticationMethods、AllowUsers/DenyUsers、Match、账户锁定和认证日志。Permission denied 本身不能确定原因。systemd VPS 重试后查日志；Alpine/OpenRC 查看系统认证日志（如 /var/log/messages 或 /var/log/auth.log）。
```sh
journalctl -u sshd -u ssh --since '3 minutes ago' --no-pager -n 60
```
