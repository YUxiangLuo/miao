# 配置参考

启动时优先读取可执行文件旁的 `config.yaml`，否则使用[平台默认路径](profiles.md#文件位置)。文件不存在也能启动，可在面板完成配置。面板无鉴权，访问限制见[平台说明](platforms.md)。

## 命令行启动

```bash
sudo ./miao --config /path/to/config.yaml
sudo ./miao --sub 'https://example.com/sub?token=xxx' JP
./miao --help
./miao --version
```

示例假定二进制名为 `miao`。`--config=PATH`、`--sub=URL` 同样有效，两者互斥；参数在提权、写文件和启核前校验。

`--sub` 接受 HTTP/HTTPS Clash YAML 订阅。地区可选 `HK/JP/TW/SG/US`，大小写不限；省略时手动选择，无地区候选时临时回退手动。临时运行默认规则分流、不限倍率，不继承已有配置或偏好，面板修改也仅影响本次运行；清理规则见 [Profile](profiles.md#sdk-与生命周期)。

订阅 URL 须加引号，令牌会进入 shell 历史和进程参数。**不支持多开**，TUN 和 Clash API 仍共享。每个订阅响应最多 4 MiB，原始 `proxies` 最多 10000 项（含被过滤节点）；超限按解析失败处理，保留已有缓存，不截断或当作成功空列表。

## 配置文件

```yaml
port: 6161
subs:
  - "https://your-subscription-url"
nodes:  # sing-box outbound JSON
  - '{"type":"hysteria2","tag":"HY2","server":"example.com","server_port":443,"password":"xxx","tls":{"enabled":true}}'
custom_rules:
  - '{"domain_suffix":"example.com","action":"route","outbound":"direct"}'
  - '{"process_name":"qbittorrent","action":"route","outbound":"HY2"}'

# 可省略；持久偏好优先于策略/倍率的启动默认值
mcp: false
node_select: manual  # 或 fastest_hk、fastest_jp、fastest_tw、fastest_sg、fastest_us
max_multiplier: null  # 不限，或正数（如 2.5）
route_mode: rule  # rule / global
scheduled_refresh:
  enabled: false
  times: ["04:30", "16:30"]  # 运行主机的本地时区，最多 24 个
```

节点支持范围见[内核能力](kernel.md#能力与裁剪)。本分支面向国内工作室：默认 `rule` 模式先将内网、中国大陆域名和 IP 直连，再按添加顺序匹配自定义规则，随后是订阅地址直连，最后使用默认代理。自定义规则不能覆盖前面的内置直连规则。DNS 同样先匹配大陆域名直连，再应用可镜像的自定义规则；来源 IP 绑定节点时，其余 DNS 查询通过该节点发送。

显式选择 `global` 会移除内置直连分流，自定义规则和订阅地址直连仍保留；需要国内直连的工作室应保持 `rule`。出口可填 `proxy`、`direct` 或节点 tag。引用缺失/禁用节点的规则会在原位置改为阻断，保留匹配条件，不回退到默认代理；`rule` 模式下前面的内网和大陆直连仍生效。原规则保留，原节点恢复后自动恢复原出口；面板显示阻断标记。

阻断由运行中的内核执行；主动停服或删除最后一个节点来源导致停服后，自定义规则无法拦截系统流量。

### 工作室：按内网 IP 固定出口

在 Linux/OpenWrt 网关运行 Miao，通过 DHCP 静态租约给电脑分配固定 IPv4 地址，并让流量经过该网关。到达 Miao 前不能先将多台电脑 NAT 成同一个来源 IP。Miao 不管理 DHCP、IP 转发或路由器防火墙，这些由网关环境配置。

导入节点后，在面板「自定义规则 → 添加 → 更多方式 → 来源 IP 地址段」填写单台电脑的 `/32` 地址，并选择指定节点。也可以在配置文件中保存相同规则，无需手写排除大陆的组合条件：

```yaml
route_mode: rule
custom_rules:
  - '{"source_ip_cidr":"192.168.50.101/32","action":"route","outbound":"员工A出口"}'
  - '{"source_ip_cidr":"192.168.50.102/32","action":"route","outbound":"员工B出口"}'
```

节点 tag 必须与实际节点一致；`proxy` 表示跟随默认出口，不能用于固定到某个具体节点。指定节点绑定不受默认节点切换或地区最快策略影响。各节点的 DNS 服务标识绑定节点 tag，避免增删节点或调整规则顺序时串用其他出口的缓存。同一来源匹配多个自定义规则时，先添加的规则生效；未绑定设备仍使用默认分流。不同节点名称不保证不同公网 IP，独立公网 IP 由出口服务提供。

本分支当前按 IPv4 接入，需在网络侧避免另一条 IPv6 出口绕过网关。局域网 DNS 应让客户端查询经过 Miao；若先交给路由器 DNS 转发器，Miao 只能看到转发器的来源 IP，无法按员工分别选择 DNS 出口。管理面板/MCP 无鉴权，应通过防火墙限制为管理员可访问。

从主分支切换后，旧运行配置缓存会被拒绝复用，并从手动节点/订阅快照重建，以应用新的路由顺序。已有持久或易变的 `global` 选择不会被自动改回 `rule`，部署时须确认当前模式。

## SOCKS5 手动节点

面板「添加节点 → 手动填写」选择 SOCKS5，填写服务器和端口；用户名、密码同时填写或同时留空（无认证）。凭据按原文保存，支持 1–255 字节，不使用其他协议的最短密码限制。

「分享链接」也支持 `socks5://user:password@proxy.example.com:1080#节点名称`、`socks://` 和 `proxy.example.com:1080:user:password`（每行一条）。链接中的特殊字符须进行 URL 编码；IPv6 地址用方括号包围。无名称的 SOCKS5 条目按本批次行号命名。Clash YAML 订阅支持 `type: socks5`，不支持 SOCKS5 over TLS；显式 `udp: false` 只启用 TCP。

底层手动配置使用 sing-box 的 `type: socks`、`version: '5'`、`username` 和 `password` 字段。标准 SOCKS5 的 UDP 转发仍取决于服务端与网络是否支持；添加节点并不代表已验证 UDP。支持 SOCKS5 的内核版本从 `miao.15` 开始，旧版本需先升级。

### 后台配置前置代理

手动节点的原始 JSON 会保留 `detour`。需要经已有节点连接 SOCKS5 服务时，可在 `config.yaml` 的对应节点中添加该字段：

```yaml
nodes:
  - '{"type":"socks","tag":"业务出口","server":"proxy.example.com","server_port":1080,"version":"5","username":"user","password":"password","detour":"前置节点"}'
```

`前置节点` 须替换为已存在且启用的具体节点 tag。链路为「网关 → 前置节点 → SOCKS5 出口 → 目标网站」。前置不要填包含当前节点的 `proxy` 选择器，也不能引用自身或形成循环。能否使用 UDP 还取决于前置节点和 SOCKS5 服务端的支持。

目前仅通过配置文件管理 `detour`，面板表单、添加/批量导入 API 和节点列表不提供该字段。修改文件不会更新运行进程的内存配置；维护时停止 Miao 后落盘，再启动主程序，避免旧面板保存时覆盖手工修改。需要延后切换时先保存独立的待生效配置。

面板与 MCP 的手动测速允许 8 秒完成探测，HTTP 请求保留 10 秒上限，为链式代理的额外握手留出时间。

## 状态保存与节点选择

稳定配置、易变状态和偏好分别保存，文件用途与位置见 [Profile](profiles.md#文件位置)。地区回退为 `manual` 不覆盖用户请求的策略，后续刷新继续尝试；具体手动节点由 `.last_proxy` 恢复。

最高倍率只筛选地区最快模式，手动选择保留完整节点池。倍率取自当前显示名，如 `18x`、`6.5X`、`2.4倍`、`倍率：1.3`；未标记按 1x，无效数值不进入受限候选。选项来自完整节点池，“不限”恢复全部候选，偏好文件用 `unlimited` 表示。

### 开机订阅刷新失败

有兼容缓存、订阅快照或手动节点时，先用本地材料启核，再后台刷新。首轮最多 20 秒，随后最多 4 次快速重试，间隔 5、10、20、40 秒（另加请求耗时）。代理已就绪但拉取仍失败时，保留运行配置并告警，转为每 30 分钟静默重试；代理未就绪且拉取失败则继续恢复；订阅已成功获取但没有可用节点时，提示检查节点配置，直接转为每 30 分钟刷新，等待节点恢复，不反复快速尝试启动。

已配置订阅 URL 的主机在分流和全局模式下默认直连，域名解析也使用直连 DNS，避免失效的默认节点阻断订阅更新。这项规则位于自定义规则之后；需要代理访问的订阅可用自定义规则指定出口，出口缺失时仍按阻断处理。自动直连仅覆盖订阅 URL 中的主机，不包含跨主机重定向的目标。

手动刷新失败不重置快速重试额度，接受响应并完成提交后结束启动恢复；停服或修改订阅取消旧任务。刷新时成功空列表不算网络失败：有替代节点则应用并删除旧节点，无候选但代理可用则保留运行态并提示检查配置。缓存可用不代表拉取成功，后台拉取也不改变代理就绪状态。API 语义见[订阅刷新](runtime-state.md#订阅刷新)。

### 删除订阅

删除优先使用剩余订阅已接受的节点快照，不强制刷新其他订阅。快照缺失、无法确认节点来源，或禁用过滤后没有可用缓存和手动节点时，才拉取剩余订阅；部分失败可沿用对应来源的缓存，有可用手动节点也可继续应用。全部拉取失败且没有可用缓存或手动节点时，保留旧配置并返回错误，禁用节点不算可用缓存。

成功返回空列表与获取失败分开处理：确认剩余来源至少一个获取成功后，即使没有可用节点，也保存删除结果，清理旧运行配置并停止代理。剩余来源的完整快照仍保留，禁用节点以后可离线重新启用。删除最后一个订阅时无需拉取，有可用手动节点则继续使用手动节点。已删除来源不会进入新快照，旧刷新任务不能将它恢复；被取消刷新的订阅行会恢复为上次结果或等待首次获取状态。

剩余订阅获取成功但没有可用节点时，先将旧运行文件和缓存移出启动路径，再保存删除结果。移除或保存失败会返回错误并恢复旧文件，保留原运行进程；旧运行文件未移出启动路径时，不会报告删除成功。此后点击启动会直接进入节点恢复流程；仍无节点时按 30 分钟间隔等待更新，不受之前刷新成功状态的影响。

规则引用已删除节点时按原有策略阻断；节点的 `detour` 若指向被删除、禁用或缺失的前置节点，仅将该节点及其依赖链从运行配置中排除，日志记录缺失依赖；绑定到这些节点的规则和对应 DNS 仍阻断。原始节点配置和快照保留，前置节点恢复后自动恢复。只要剩余节点能构成有效配置，就允许应用，不要求节点连通性测试通过；全部节点依赖失效也不能算手动兜底。其他配置校验、启动或持久化失败仍会回滚。

### 定时刷新订阅

在订阅管理点击「定时刷新」，或用 MCP `set_scheduled_refresh` 设置。配置保存在 `config.yaml`，热生效、不重启内核。

- 使用**运行主机的系统时区**，时刻为 `HH:MM`，最多 24 个；面板显示该时区与下次执行时间，不随浏览器时区换算。
- 到点复用手动刷新的拉取、生成、校验和应用路径。全部来源失败、事务失败、初始化未完成或前台刷新占用时，按 1/5/15 分钟重试，最多 3 次且不越过下个计划时刻。
- 部分来源失败不重试：成功来源提交，失败来源沿用缓存。成功、无需执行或到达下个计划时刻时清零预算；用尽后等下个时刻。退避原因只写日志，可用 `journalctl -u miao` 查看；订阅行与告警同手动刷新。
- 调度仅在 Miao 进程存活时运行。内核停止时仍更新配置，但不会自动启核；调度退避不重置启动恢复预算。

### 禁用订阅节点

点击订阅卡片的节点数量可禁用/启用节点。禁用节点不进入配置，引用它的规则会阻断匹配流量；操作后节点池为空（含手动节点）返回 400。

禁用集存于 `volatile.yaml`，按“订阅 URL + 节点名”匹配；同名节点一起禁用，改名后旧条目失效。默认易变层随系统重启清空：

```yaml
disabled_nodes:
  - sub: "https://your-subscription-url"
    name: "香港 01"
```

## 连接检查

面板「连接检查」、REST `/api/connectivity` 和 MCP `test_connectivity` 共用一次 HTTP/HTTPS HEAD 请求，超时 5 秒，不修改配置。请求从 **Miao 主机**发起，忽略 HTTP_PROXY/HTTPS_PROXY，但仍可能经过系统 TUN；不代表浏览器或指定节点的连通性。

`success` 仅表示收到 HTTP 响应，须结合 `http_status`、`error_kind`（timeout/connect/request）和 `error` 判断。403/405/503 不代表访问正常，部分网站不支持 HEAD；后端不可达也不能当作目标不可达。关闭弹窗不取消检查，报告保留至下次检查或刷新页面；复制失败可手动选取。

## VPS 一键部署

「添加节点 → VPS 部署」通过 SSH 安装 Hysteria2 或恢复已有 Miao 节点。Miao 主机须有 OpenSSH 客户端。

- 目标为 Linux x86_64/arm64、systemd/OpenRC、POSIX sh；自动安装依赖支持 apt、dnf/yum、apk、pacman、zypper，其他环境须预装工具。
- 仅支持 **root 密码登录、SSH 22 端口**，不支持密钥或非 root sudo；密码只用于本次连接，不写入 Miao 配置。
- 固定版本经官方校验清单验证后才替换服务。Hysteria2 使用 **543/UDP**，须在安全组与 VPS 防火墙放行。

错误详情保留至关闭或重试。`Permission denied` 不能区分密码错误与服务端禁用登录；面板「查看解决办法与错误详情」提供[条件化排障步骤](../crates/miao-core/src/services/vps/ssh-auth-help.txt)，Miao 不自动执行修复。主机密钥变化时先核对服务商指纹，再更新运行 Miao 账户的 `known_hosts`。

## MCP：让 AI agent 操作代理

设置 `mcp: true` 或打开顶部 MCP 开关，端点为 `http://<面板地址>/mcp`；关闭时返回 404。Claude、Codex 图标可复制添加命令；「AGENTS.md」按钮复制端点、常用工具和确认约定，不自动配置客户端，agent 须能访问该地址。复制失败时弹窗保留文本。

使用 MCP `2025-11-25` Streamable HTTP：先 `initialize`，再 `notifications/initialized`，后续请求携带 `MCP-Protocol-Version`；无 session、无 SSE，启用时 `GET /mcp` 返回 405。用 `tools/list` 获取工具和参数，覆盖状态、连接、启停、节点、订阅、规则、定时刷新、VPS 与升级；平台不支持的操作返回明确错误。主题、弹窗、PWA、分享链接解析在浏览器本地完成，结构化节点用 `add_node` / `import_nodes` 导入。

停止、删除、部署、关闭 MCP、升级等工具要求 `confirm: true`，调用前须获用户明确确认。订阅 URL、连接记录和 VPS 密码应保密；热应用可能影响当前连接。MCP 与面板共用[无鉴权的访问边界](platforms.md#访问与持久化)。
