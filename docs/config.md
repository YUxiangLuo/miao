# 配置参考

默认查找可执行文件旁的 `config.yaml`，没有则使用平台默认路径；`--config` 可显式指定。配置文件不存在时也能启动并在面板完成配置。目录与隔离规则见 [Profile 与路径归属](profiles.md)。

## 命令行启动

```bash
sudo ./miao --config /path/to/config.yaml
sudo ./miao --sub 'https://example.com/sub?token=xxx' JP
./miao --help
./miao --version
```

`--config=PATH`、`--sub=URL` 同样有效。`--sub` 接受 HTTP/HTTPS Clash YAML 订阅，与 `--config` 互斥；参数在提权、文件写入和内核启动前校验。

每个订阅响应最多 4 MiB，原始 `proxies` 列表最多 10000 项（包含随后会被过滤的节点）。超过限制按订阅解析失败处理，不截断列表，也不当作成功空列表；已有缓存仍按通常的失败恢复规则使用。

地区可选 `HK / JP / TW / SG / US`，大小写不限；省略时手动选择，无该地区候选时临时回退手动并保留地区偏好。`--sub` 使用独立临时 Profile，默认规则分流、不限倍率，不读取已有配置或偏好；面板修改也仅属于本次运行。正常退出后清理，强杀、断电或进程替换升级可能留下临时目录，但后续运行不会复用。

订阅 URL 须加引号，并留意令牌会进入 shell 历史和进程参数。Profile 隔离不支持多开，TUN 和 Clash API 仍共享，不要与已有实例同时启动。

## 配置文件

```yaml
port: 6161
subs:
  - "https://your-subscription-url"
nodes:  # sing-box outbound JSON，支持范围见内核文档
  - '{"type":"hysteria2","tag":"HY2","server":"example.com","server_port":443,"password":"xxx","tls":{"enabled":true}}'
custom_rules:
  - '{"domain_suffix":"example.com","action":"route","outbound":"direct"}'
  - '{"process_name":"qbittorrent","action":"route","outbound":"香港节点"}'

# 以下均可省略；策略/倍率的持久偏好优先于启动默认值
mcp: false
node_select: manual  # manual / fastest_hk/jp/tw/sg/us
max_multiplier: null  # 不限，或正数（例如 2.5）
route_mode: rule  # rule / global

# 定时刷新订阅（稳定层，面板/MCP 可改）：每天的执行时刻，系统本地时区，最多 24 个
scheduled_refresh:
  enabled: false
  times: ["04:30", "16:30"]
```

手动节点支持七种协议，见[内核能力](kernel.md#能力与裁剪)。自定义规则优先于内置分流，全局模式下仍生效；出口可填 `proxy`、`direct` 或节点 tag，引用缺失/禁用节点的规则会跳过并在面板标记。Windows 进程名需带 `.exe`。

## 连接检查

面板「连接检查」可对指定 HTTP/HTTPS 网址发起一次 HEAD 请求，超时为 5 秒，不修改配置。检查从 **运行 Miao 的主机**发起，不使用 HTTP_PROXY/HTTPS_PROXY 环境变量，但仍可能经过系统 TUN 和路由；它不等于浏览器或指定代理节点测试。服务就绪也不代表任意网站可达。

结果显示 HTTP 状态或失败类型，并提供下一步建议和可复制报告。HTTP 403/405/503 等表示已收到响应，但不能据此宣称访问正常；部分网站不支持 HEAD。关闭弹窗不会中止检查，报告保留到下次检查完成或页面刷新。复制失败时会选中报告，方便手动复制。

REST `/api/connectivity` 和 MCP `test_connectivity` 共用检查实现。结果中的 `success` 保持“收到 HTTP 响应”的含义；结合 `http_status`、`error_kind`（timeout/connect/request）和 `error` 判断，不要把后端连接失败误判成目标网站不可达。

## VPS 一键部署

面板「添加节点 → VPS 部署」通过 SSH 安装 Hysteria2，也可恢复已有 Miao 部署的节点。运行 Miao 的设备须有 OpenSSH 客户端；Windows 面板不提供此功能。

- 目标为 Linux x86_64/arm64 VPS，使用 systemd 或 OpenRC。依赖安装适配 Debian/Ubuntu（apt）、Fedora/RHEL 系（dnf/yum）、Alpine（apk）、Arch（pacman）和 openSUSE（zypper）；没有对应包管理器时须预装所需工具。远端仅需 POSIX sh，不依赖 bash。
- 当前使用 **root 密码登录、SSH 22 端口**，不支持密钥或非 root sudo 登录。密码只用于本次连接；不会写入 Miao 配置。
- 使用固定版本及官方校验清单，下载校验成功后才替换已有服务。Hysteria2 监听 **543/UDP**，须在服务商安全组及 VPS 防火墙中放行。
- 失败原因保留在部署窗口，可展开、选取错误详情，手动关闭或重试后清除。错误区分认证拒绝、连接拒绝/超时、DNS/路由问题、主机密钥变化、依赖安装及服务启动失败。

`Permission denied` 不能单独证明密码错误：服务端禁用 root 登录或密码认证也可能返回相同错误。请通过服务商控制台检查密码、sshd 的 `PermitRootLogin` / `PasswordAuthentication`、`Include` / `Match` 覆盖项及认证日志；仅允许密钥的 VPS 暂不适用当前部署方式。主机密钥变化时，先核对服务商提供的指纹，再更新运行 Miao 账户的 `known_hosts`。

认证失败时，面板「查看解决办法与错误详情」提供逐步说明和可复制命令：先用 `sshd -T` 检查实际生效值，再定位配置片段。若确认 `50-cloud-init.conf` 提前设置了 `PasswordAuthentication no`，可按提示新增更早加载的本地配置，经 `sshd -t` 校验后重新加载服务。修复命令不会覆盖已有同名文件；存在 `Match` 条件时需按实际连接进一步核对。Miao 不会自动执行这些命令。

## 状态保存与节点选择

| 文件 | 保存内容 |
| --- | --- |
| `config.yaml` | 订阅、手动节点、规则、端口、MCP 开关及启动默认值 |
| `volatile.yaml` | 当前策略、倍率、路由模式和禁用的订阅节点 |
| `.node_select` / `.max_multiplier` / `.last_proxy` | 显式选择的策略、倍率和具体手动节点 |
| `config.json`、运行缓存、订阅快照 | 派生运行状态，可重新生成 |

具体位置和平台持久化差异集中在[路径表](profiles.md#文件位置)。默认 Unix 易变层在 tmpfs；OpenWrt/非 systemd 的选择偏好也在 tmpfs，进程重启时保留，系统重启后回到 YAML 启动默认值。systemd Linux 和 Windows 会持久保存选择偏好。

地区无候选而回退 `manual` 不覆盖用户请求的策略，后续刷新继续尝试原地区。首次升级会迁移旧易变层中明确记录的倍率和 `fastest_*`，但不将无法区分来源的 `manual` 提升为持久偏好。具体手动节点由 `.last_proxy` 独立恢复。

最高倍率只影响地区最快模式的自动候选，手动选择仍保留完整节点池。倍率从当前显示名识别（如 `18x`、`6.5X`、`2.4倍`、`倍率：1.3`）；未标记按 1x，明确标记但数值无效的节点不进入受限候选。下拉选项来自完整节点池，选择“不限”可恢复全部自动候选，偏好文件用 `unlimited` 表示不限。

### 开机订阅刷新失败

有兼容缓存、订阅快照或有效手动节点时，先用本地材料启核，再后台刷新。首轮最多 20 秒，随后最多 4 次快速重试，间隔 5、10、20、40 秒（另加请求耗时）。代理已就绪但订阅仍失败时，保留运行配置并告警，改为每 30 分钟静默重试。

手动刷新失败不重置快速重试额度，成功则结束启动恢复任务；停服或修改订阅会取消旧任务。代理本身尚未就绪时仍继续恢复，不受上述次数限制。刷新活动与代理状态独立，后台拉取不会把就绪的代理改成“启动中”。

成功空列表不算网络失败：有替代节点时正常应用并清理旧订阅节点；没有可用候选且当前代理可用时保留运行态，提示检查订阅或禁用设置，不反复获取空列表。缓存可用不代表本轮拉取成功。API 语义见[状态文档](runtime-state.md#订阅刷新)。

### 定时刷新订阅

在订阅管理标题栏点「定时刷新」，或用 MCP `set_scheduled_refresh` 配置。设置属于稳定层，随 `config.yaml` 保存、修改后热生效，不重启内核。

- 时刻按**运行主机的系统时区**解释和执行，格式 `HH:MM`，最多 24 个；面板展示系统时区（IANA 名与 UTC 偏移）和下次执行时间，从其它设备打开面板也不会换算成浏览器时区。
- 到点后复用面板手动刷新的同一条路径（拉取 → 生成 → 校验 → 热应用）；一直有前台刷新在进行时跳过本次，留到退避重试。
- 仅“全部来源失败”或事务硬失败（如生成、`sing-box check`、提交失败）才按 1/5/15 分钟退避重试（最多 3 次，且不越过下个计划时刻）；到点时初始化尚未完成或已有前台刷新也按同一预算重试。
- **部分来源失败不算失败**：与手动刷新、启动恢复同口径，成功来源正常提交、失败来源沿用缓存节点，不重试。成功、无需执行或到达下个计划时刻会清零预算，用尽后等下一个时间点。重试与失败原因只写日志（systemd 安装可用 `journalctl -u miao`），面板订阅行与告警与手动刷新一致。
- 调度只在 Miao 进程存活期间运行（systemd 服务、托盘或前台进程）；服务处于停止状态也会刷新并更新配置，但不会自动启动内核。

### 禁用订阅节点

在订阅卡片点击节点数量，可逐个禁用/启用。禁用节点不进入生成配置，引用它的规则也会跳过；操作后节点池为空（含手动节点）会返回 400。

禁用集由面板维护在 `volatile.yaml`，按“订阅 URL + 节点名”匹配，同订阅内同名节点一起禁用；改名后旧条目失效。默认 Unix 易变层随系统重启清空。

```yaml
disabled_nodes:
  - sub: "https://your-subscription-url"
    name: "香港 01"
```

## 网络活动分析与 24 小时日志

点击顶部流量区域，在「链接统计」中选择「24 小时分析」或「原始日志」。停止代理后仍可查看历史；没有历史时显示空状态，不回填旧版 `miao.log`。

1／6／24 小时是查询的最大回看窗口。趋势图从窗口内首条日志或采样所在的 5 分钟分桶开始，不把尚未有记录的前段补成零；零流量采样也算记录。横轴包含日期，首尾分桶可能不完整。中间桶的零表示没有相应已保存记录，不证明服务始终在线或采集无丢失；没有 DNS 完成事件的延迟桶留空，单个数据点也会显示。

- **活动概览**：日志量与错误级别趋势、组件／事件分布、关联上下文；支持从排行下钻到原文，再查看同一内核批次、同一上下文的日志。
- **DNS 行为**：域名／类型／上游／结果分布，真实耗时 P50/P95/P99 和最慢单次事件；展示完成量、非成功量、P95 与最大耗时趋势。排行可按次数、域名最大耗时、域名非成功次数切换，各排行从完整时段独立计算 Top 20，不在热门域名子集中重排；非成功占比的分母是该域名的完成事件数。域名点击后在 DNS 原文中搜索。耗时由定制内核 `miao.9` 的单调时钟测量，含规则、缓存与等待；不是日志前缀中的上下文年龄。`LOOKUP` 表示完整解析，可能包含 A/AAAA；未完成的调用不在完成事件中，未知上游显示未记录。失败包含非零 DNS RCODE，不等同网络传输失败。缓存答案日志不是查询次数，面板不据此宣称命中率。
- **分流与出口**：分别计算入站、出口组件活动排行，以及规则匹配和路由／连接事件；组件活动包括各级别日志，出站发起不表示连接成功，匹配记录可包含中间规则判断，不等同最终连接数。
- **错误与告警**：分开统计 ERROR/FATAL/PANIC、WARN 和 DNS 非成功完成，按组件与级别聚合日志数、组内去重上下文数和最近出现时间，支持保留时段下钻。来源表按日志数展示 Top 20；上下文不可跨组相加，错误条数不是连接失败率，也不代表已识别根因。
- **流量采样**：单独使用 Clash API 每 3 秒采样的计数增量，按域名、来源、进程、出口、规则和网络类型聚合。短连接和关闭前最后字节可能遗漏，不能用于精确计费。
- **日志覆盖**：将已保存记录分成「已分类事件」「仅识别前缀」「未识别前缀」三个互斥集合，提供未分类／未识别日志下钻及级别分布。识别前缀不代表理解正文，覆盖统计也不能证明采集无丢失。解析规则变更只影响新入库记录，不重写已有事件索引。
- **原始日志**：保存内核运行进程 stdout/stderr 的完整行与原始字节，按级别、文字、组件、事件和上下文检索，游标翻页；异常文本也保存。页面时间是 Miao 收到记录的时间，原始内核时间保留在原文中。上下文 ID 是关联线索，不保证与 DNS 请求或 Clash 连接一一对应。

DuckDB 放在配置所属的 `.miao-profiles/<配置路径哈希>/analytics/network.duckdb`；显式覆盖运行目录时放在 `<runtime_dir>/analytics/network.duckdb`，临时 Profile 随其临时目录清理。常规 Profile 跨重启保留数据，启动、后台每分钟及正常关闭时清理超过 24 小时的记录，所有查询也限制 24 小时窗口。清理后的磁盘块可被 DuckDB 重用，文件大小不保证立即收缩，也不属于安全擦除；停止 Miao 期间不运行清理。

新生成内核配置开启 `trace`、关闭颜色；恢复旧配置缓存时沿用旧级别，下一次成功生成配置后生效。已完成批次事务落盘；突然掉电／强制终止可能丢失尚未提交的批次。磁盘故障会告警并重试，积压产生背压可能影响内核；正常关闭等待日志排空，故障下最多等待每个采集任务 5 秒。不承诺磁盘耗尽时无损。当前实现优先分析能力，尚未针对 OpenWrt 存储与写入压力优化。

日志含访问域名、地址、进程及可能的敏感错误信息，不包含抓包载荷。Unix 存储目录权限为 `0700`；历史 API 与现有面板共用访问边界，**面板无鉴权，切勿暴露到不可信网络**。支持只读 `GET /api/analytics/summary?hours=1|6|24` 和 `GET /api/analytics/logs`；后者可传 `hours`、`level`、`q`、`component`、`event`、`context`、`id`、`before`、`limit`（1–500）。没有任意 SQL 执行接口。

### 分析存储的写入与查询

采集仍以最多 256 条／约 1 MiB／250 ms 触发批次，保留原始字节和失败重试。批次使用 DuckDB Appender 写入日志及 DNS 事件，ID 从原有序列一次分配并排序后按输入顺序使用；显式检查两张表的 flush 错误，再一起提交。回滚允许序列出现空隙，不允许半批数据留在表中；不迁移旧数据库、不重写已有日志。

写入、采样和保留期清理继续共用一个写连接；面板查询串行复用另一个连接，不再等待写连接的应用层互斥锁。每次查询使用事务快照，摘要中的多个 SQL 看到相同的已提交状态。清理四张表也在同一事务内完成，然后执行 CHECKPOINT。活动读快照可能延迟旧版本的磁盘空间回收；两条连接仍共享数据库的 CPU、内存和 I/O，不代表查询与写入完全没有资源争用。

Linux amd64 / Ryzen 5 5600 / DuckDB 1.5.5，本仓库 release 配置、Btrfs 工作区临时文件数据库的本地对照结果如下。每组交替执行新旧路径 6 轮，表中为中位数；写入项每轮连续提交 10 个批次，包含解析、事务提交，但不含数据库初始化与采集器等待时间。

| 负载 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 单条普通日志 | 4.05 ms | 4.01 ms |
| 256 条普通日志 | 36.80 ms | 5.85 ms |
| 256 条混合日志（25% DNS 完成事件） | 57.41 ms | 6.30 ms |
| 256 条 DNS 完成事件 | 109.35 ms | 7.16 ms |
| 完整分析摘要查询期间提交 256 条 DNS 日志 | 41.34 ms | 7.27 ms |

最后一项使用 16,384 条历史日志（4,096 条 DNS 事件，无流量采样记录），两组均已启用 Appender，仅对比共用连接锁与独立查询连接；检查旧摘要仍保持原快照，新查询能看到完整新增批次。稀疏写入没有确定收益，在 tmpfs 对照中仍有少量固定开销；上述批量收益不能换算成代理吞吐提升或所有磁盘上的固定倍率。

复测仅创建并删除临时数据库，不读取运行实例的数据。指定磁盘目录可避免把 `/tmp` 的 tmpfs 结果当成磁盘写入性能；普通测试默认跳过这两个基准。

```bash
mkdir -p .cache
TMPDIR="$PWD/.cache" cargo test --locked --release -p miao-core \
  analytics::tests::benchmark_ -- --ignored --nocapture --test-threads=1
```

### 连接快照请求合并

分析采样和面板的普通 `GET /api/clash/connections` 共用进行中的上游请求，不缓存已完成的结果；下一次轮询仍重新读取计数，不引入固定 TTL 导致速率归零后跳高。内核生命周期代次变化时不复用旧请求，采样落盘前也复核代次和进程身份。DELETE 等写操作仍透传，并在请求前后使已有共享请求失效；带查询参数、请求体或 Content-Type 的 GET 保持独立透传。

采样等待上限仍为 2 秒，上游请求上限为 10 秒。单个等待者取消或超时不会取消其他等待者；最后一个等待者消失后释放上游请求。状态码、Content-Type 和原始响应字节保持不变，包括非成功响应；失败结果不缓存。

隔离回环 HTTP 测试验证 32 个重叠调用只发起 1 次上游请求，之后的调用读取新结果，并覆盖代次切换、失效、取消、超时及响应体截断。**这是重叠请求的去重，不是将常态采样开销降低固定比例**：采样与页面轮询错峰时不会减少请求数，也未据此宣称代理吞吐提升。测试不连接运行实例：

```bash
cargo test --locked -p miao-core state::connections
cargo test --locked -p miao-core handlers::clash
```

## 本地 AI 网关

点击左上角猫头，在代理页面与独立的「AI 网关」页面之间切换；规则卡片中的固定「AI 网关」项也可进入该页面。支持通过 `#ai` 直接进入、刷新和浏览器前进/后退。AI 分流管理**经过本机网关的 API 请求**，不是 AI 网站域名规则。默认关闭，需要 Miao 代理内核及至少一个可用节点；暂停代理时网关拒绝推理请求，不自动直连。支持 OpenAI 兼容的 `GET /v1/models`、`POST /v1/chat/completions`，以及按供应商显式开启的 `POST /v1/responses`。不支持 ChatGPT/Claude 订阅登录、账号转换、任意路径透传或协议转换。

1. 打开「AI 网关」配置，按页面显示的路径，在运行 Miao 的机器上读取 `admin-token.txt`，粘贴管理员令牌解锁。它与客户端密钥不同。
2. 添加供应商，填写 **HTTPS API 根地址**、API Key，以及公开模型别名 → 上游模型 ID。例如 OpenRouter：`https://openrouter.ai/api/v1`，Fireworks：`https://api.fireworks.ai/inference/v1`。其他 OpenAI 兼容供应商可修改同一表单的名称和地址。不要把 `/chat/completions` 加入 Base URL。
3. 生成客户端访问密钥并立即复制。旧密钥不可再次读取；轮换立即阻止旧密钥的新请求，已开始的请求不追溯撤销。
4. 选择出口：跟随全局代理、指定节点，或**显式直连**。配置供应商和模型后启用并保存。指定节点消失时拒绝请求，不切换到其他节点。仅切换可用出口不重启内核；保存后的新请求换用新连接池，已建立的流继续使用旧连接。启停网关或更改内部代理端口需要应用内核配置，可能中断连接。
5. 将 AI 客户端 Base URL 设为 `http://127.0.0.1:6162/v1`，API Key 使用刚生成的客户端密钥，模型填写公开别名。端口可修改，API 与内部代理默认分别为 `6162`、`6163`，仅监听 IPv4 回环，不能相同或占用面板/Clash 端口。网关地址属于 **Miao 所在机器**，不是远程浏览器所在机器。

```bash
# MIAO_AI_KEY 是生成的客户端密钥，不是供应商 API Key。
curl http://127.0.0.1:6162/v1/chat/completions \
  -H "Authorization: Bearer $MIAO_AI_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"assistant","messages":[{"role":"user","content":"Hello"}],"stream":true}'
```

请求只改写顶层 `model`，工具调用、图像内容和供应商扩展参数原样转交；上游响应与 SSE 字节不改写。网关不自动重试计费请求、不跟随重定向、不把本地密钥/cookie 转发给供应商。连接超时 15 秒，等待响应头和流空闲超时各 120 秒，持续输出的流没有总时长限制；请求体上限 8 MiB。`/v1/models` 返回已配置的别名，不自动获取供应商模型目录。「已就绪」表示本地监听、内核及所选出口可用，不代表供应商密钥、余额或模型已验证。

密钥保存在配置所属的 `.miao-profiles/<配置路径哈希>/ai/`，不进入普通 `config.yaml`；供应商密钥以明文保存在受权限保护的 `settings.json`，客户端密钥只保存哈希。Unix 目录 `0700`、文件 `0600`；Windows 使用仅所有者和 SYSTEM 可访问的目录 ACL。保护备份，不要将该目录纳入版本控制。管理接口为 `/api/ai/settings` 和 `/api/ai/access-key`，需要管理员 Bearer 令牌，读取设置只返回 `has_key`；`/api/ai/status` 只公开运行信息与令牌文件路径。切换回代理页面、刷新或点击「锁定配置」后清除令牌和未保存的配置/密钥草稿，不写入浏览器存储；锁定页面不会停用网关。网关推理端点拒绝带 Origin 的浏览器请求，仅面向本机 API 客户端。

**这不是给整个面板增加鉴权。** 现有面板/MCP 仍须限制在可信网络。远程管理密钥时使用 HTTPS 或 SSH 隧道，勿通过不可信网络的明文 HTTP 粘贴令牌。网关默认不记录提示词、响应正文或供应商密钥；既有网络活动分析仍可记录供应商域名和连接元数据。

### AI 请求与用量统计

解锁后可切换「用量概览」「请求记录」「网关配置」。统计页按最近 24 小时、7 天或 30 天查看，支持供应商 ID、模型别名和结果精确筛选，记录每页 100 条；模型汇总显示请求数前 100 组。页面手动刷新，查询接口 `/api/ai/analytics` 与配置接口使用相同管理员鉴权，不向公开状态接口暴露记录。

统计使用**现有 `analytics/network.duckdb`** 的独立 `ai_requests` 表与读写连接，没有新增 SQLite 或第二个数据库。AI 记录保留 30 天，网络记录仍保留 24 小时；沿用启动、每分钟和正常关闭时的清理，查询也限制保留期。

- 只统计通过鉴权、请求格式有效且已匹配模型的推理请求；不含模型列表、无效密钥、未知模型和请求体拒绝。请求结束后写入，运行中不显示。按请求开始时间归入窗口。
- 保存供应商 ID、公开别名、上游模型、接口、流式标志、结果、上游 HTTP 状态、耗时和用量，不保存正文、原始错误消息、请求头或密钥。区分客户端取消、网关停止、连接失败、超时、上游 HTTP/API 错误和流中断。
- 总耗时从模型匹配后开始，包含出口准备和响应传输；首字节耗时是首个响应正文数据块到达时间，**不是首 token 延迟**。平均值和 P95 包含当前筛选范围内所有已结束请求。
- Token 仅使用上游 `usage`，支持普通 JSON 与 SSE 的 Chat Completions / Responses 格式。缺失显示「未知」，不猜测、不视为已测得零；取消或中断后的部分用量不计入完整汇总。概览显示完整用量的请求覆盖数，费用暂不估算。对 SSE 还要求收到 `[DONE]` 或 `response.completed` 完成标志。
- 网关不自动注入 `stream_options`；流式 Chat 客户端可按供应商支持情况传入 `"stream_options":{"include_usage":true}`。单个 JSON 响应或待解析 SSE 事件的检查缓冲限制为 1 MiB，超限停止用量检查但继续原样转发。超限时结果只能按 HTTP/传输是否结束判断，不保证识别正文中的 API 错误。
- 写入使用最多 256 个待完成任务，复用串行写连接；积压或写入失败会丢弃记录并在统计页告警，不阻塞推理。丢失计数与告警仅覆盖本次运行。正常关闭最多等待统计写入 5 秒；强制终止可能丢失进行中或未提交记录，**不能作为精确账单**。

隔离测试（Linux amd64，需要 sudo、网络命名空间和已构建内核）运行 `./scripts/test-ai-transport.sh`，覆盖真实 CONNECT/TLS、不同出口、连接池更换、超过 30 秒的 SSE、断开取消和拒绝回落。测试供应商与密钥均为本地合成数据，不调用收费 API，不启动 TUN 或操作运行实例。

## MCP：让 AI agent 操作代理

设置 `mcp: true` 或使用面板顶部 MCP 开关，连接 `http://<面板地址>/mcp`；关闭时返回 404。顶部的 Claude、Codex 图标可复制对应客户端的添加命令。当前实现 MCP `2025-11-25` Streamable HTTP：先 `initialize`，再 `notifications/initialized`，后续请求携带 `MCP-Protocol-Version`；无 session、无 SSE，启用时 `GET /mcp` 返回 405。

旁边的「AGENTS.md」按钮可复制简短 Markdown 使用说明，包含当前端点、常用工具及操作确认约定，可粘贴到项目的 `AGENTS.md`。说明不会自动配置 MCP；agent 须能访问该地址。浏览器复制失败时，弹窗保留文本供手动选取复制。

用 `tools/list` 获取完整工具和参数。工具覆盖状态、流量/连接、启停、节点策略/倍率、切换/测速、订阅、定时刷新、手动节点、规则、MCP 开关、VPS 部署和升级；平台不支持的操作返回明确错误。主题、弹窗、PWA 和分享链接解析属于浏览器本地功能；结构化节点可通过 `add_node` / `import_nodes` 导入。

停止、删除、部署、关闭 MCP、升级等破坏性工具要求 `confirm: true`，调用者须先获得用户明确确认。订阅 URL、连接记录和 VPS 密码应保密；流量可能正经过本代理，热应用配置可能影响连接。

**面板和 MCP 无鉴权。** Linux 默认监听 `0.0.0.0`，局域网设备也可调用；Windows 仅监听 `127.0.0.1`。不要直接暴露到不可信网络。
