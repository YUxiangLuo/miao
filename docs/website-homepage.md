# Miao 官网设计方案（首页篇)

> 目标：为 Miao 设计并搭建官方网站。本文档描述首页应当长什么样，作为后续实现的设计稿与需求文档。
> 依据：对项目本体（README、面板 UI、功能集）的一手了解，所有功能描述均已与代码核实。

## 1. 定位与受众

**一句话定位**：开箱即用的透明代理。

**受众画像**（按优先级）:

1. 中文 Linux 桌面/服务器用户——想要分流代理但不想折腾内核配置、防火墙和面板拼装
2. OpenWrt/软路由用户——想给整台路由器的设备做透明代理
3. NAS/家庭实验室玩家——长期开机、需要 systemd 常驻与自升级

**受众的决策路径**：扫一眼 Hero（这是啥）→ 看 30 秒上手（真的这么简单？)→ 看面板截图（长什么样）→ 看功能列表（有没有我要的 X)→ 点 GitHub/下载。首页所有 section 都为这条路径服务。

**语言**：中文为主（项目 README、面板均为中文，核心受众是中文用户）。预留 i18n 结构，英文版后置。

**交互**:Hero 下方直接露出 S2 的终端代码块上缘，引导滚动。

### S2. 30 秒上手（Quickstart)

**目标**：证明"真的只要 30 秒"。这是全站转化率最高的 section，放第二位。

**内容**：终端风格的代码块（深色卡片 + macOS 三点装饰 + 一键复制按钮）:

```bash
mkdir -p ~/miao && cd ~/miao
wget https://github.com/YUxiangLuo/miao/releases/latest/download/miao-rust-linux-amd64 -O miao
chmod +x miao && sudo ./miao
```

- 下方三行注解：arm64 换文件名；浏览器打开 `localhost:6161` 按引导添加订阅/节点；需要 root(TUN 所需）
- 次要链接：「安装为 systemd 服务」→ 展开/收起 `sudo bash install.sh ./miao` 及管理方式；「卸载」→ `sudo bash remove.sh`

**交互**：复制按钮点击后变 ✓；amd64/arm64 切换 tab（切换代码块里的文件名）。

### S5. 独特卖点 Spotlight：进程级分流

**目标**：把差异化功能单独放大。同类单文件工具里，"对某个进程指定出口节点"几乎没人做得这么省心。

**形式**：左文右码（或上文下码）:

- 文案：场景化举例——「让 qbittorrent 永远直连不耗机场流量；让 `codex`/`gpt` 固定走低延迟节点；浏览器照旧规则分流。进程名或路径匹配，节点下拉即选，失效自动跳过并在面板提醒。」
- 代码块（取自 README 配置参考，真实可用）:

```yaml
custom_rules:
  - '{"process_name":"qbittorrent","action":"route","outbound":"direct"}'
  - '{"process_name":"codex","action":"route","outbound":"香港节点"}'
```

- 可配一张规则卡局部截图（面板中 codex → Deguo 那两行的裁剪，需注意打码）

### S6. 工作原理

**目标**：给技术用户"它没做黑魔法"的信任感。

**形式**：居中架构图（由 README 的 ASCII 图重绘为 SVG):

```
┌─────────────┐   TUN    ┌──────────────────┐   Clash API   ┌─────────┐
│  本机全部流量  │ ───────▶ │ 内嵌 sing-box 内核 │ ◀──────────▶ │ Web 面板 │
└─────────────┘          │ geoip-cn + 直连域名 │  127.0.0.1   │ (内嵌)   │
                         │ 规则集决定分流去向   │              └─────────┘
                         └──────────────────┘
```

配三条要点：TUN 透明代理不碰 iptables;DNS 双轨与乐观缓存；配置变更先 `sing-box check` 再热重启，失败回滚。

### S8. FAQ

**目标**：扫除最后的顾虑。建议条目（答案均已与代码核实）:

1. **为什么需要 root?** —— TUN 透明代理必须。面板本身不需要额外依赖。
2. **支持 OpenWrt 吗？** —— 支持。自动检测并安装依赖；运行时文件只在 /tmp，不写 flash。
3. **我的配置存在哪？** —— 不创建任何文件也能用；持久化按 `--config` 指定路径 → 可执行文件同目录 → `/etc/miao/config.yaml` 顺序查找。节点选择与分流/全局模式写在 tmpfs 的易变层（`volatile.yaml`），不写闪存，系统重启后回到 config.yaml 的启动默认值。
4. **怎么卸载干净？** —— `sudo bash remove.sh`：服务、二进制、配置、运行时文件、残留进程与网卡全部清理。
5. **面板有鉴权吗？** —— 没有。面板监听 `0.0.0.0:6161`，请在可信局域网使用，勿暴露公网。（诚实说明反而是加分项）
6. **节点从哪里导入？** —— Clash YAML 订阅 / 分享链接（hy2、ss、vmess、vless、trojan、tuic、anytls)/ VPS 一键部署。

## 4. 交互与动效原则

- **少即是多**：仅保留复制按钮反馈、代码块 tab 切换、FAQ 折叠（`<details>` 即可）。不做滚动视差、不做入场动画轰炸——与面板的工程气质一致
- 整站单页、锚点导航（顶部吸顶栏：功能 / 快速上手 / 原理 / 下载 / FAQ)
- 移动端单列，截图缩放；代码块横向滚动
- 首屏性能：截图 `loading="lazy"`(Hero 除外）,SVG 图标内联，无第三方 JS

## 5. 技术方案建议

- **构建**:Astro（内容型静态站首选，产物零 JS 或极少 JS）或 Vite + React（与主项目栈复用）。若预期后续加文档页，Astro + Starlight 一条线更顺
- **部署**:GitHub Pages（与仓库同 org，免费）或 Cloudflare Pages；CI 里加一条官网构建发布 workflow
- **域名**：短期用 `<user>.github.io/miao` 或 `miao.pages.dev`，长期可考虑独立域名
- **SEO/分享**:OG/Twitter Card 用打码后的面板截图生成 1200×630 卡片图；`<html lang="zh-CN">`;meta description 用 slogan
- **分析**：可不要；若要，用 Plausible/Umami 这类无 cookie 方案
